# 模型目录索引优化验收

验收日期：2026-10-27。修改集中在模型资料匹配和官方协议查找。软件及官网均未发布，本轮未替换交付安装包。

## 算法与资料更新

旧实现为每个模型逐级扫描全部参考记录，并重复执行名称、格式和日期处理。新实现先按整份资料建立索引，再按精确名称、别名、格式和日期依次查询。优先级、同目标首条记录及歧义阻断保持原语义。

可更新能力资料每次加载都读取最新快照，索引只在本轮批量处理中复用。没有跨快照的长期匹配结果或未命中缓存。磁盘文件大小及修改时间不作为资料一致性的依据。仅不可变的内置资料和官方协议索引在进程内复用。

更新能力、删除能力、同大小及同修改时间的资料替换、服务能力优先级和服务隔离检查均通过。目录请求与资料刷新重叠时，原有代数校验会使用当前资料重新处理，相关原生回归通过。

## 性能与准确性

以下为实际 Windows Rust 后端的完整 RPC 往返耗时，采用生产使用的发布优化配置。上游为本机合成服务，真实网络时间另计。每组运行 3 次，表中为中位数；第一个 200 模型请求包含内置资料初始化，后续规模在同一进程中测量。

| 模型数 | 刷新目录 | 读取缓存 |
| --- | --- | --- |
| 200 | 0.271 秒 | 0.110 秒 |
| 1,000 | 0.169 秒 | 0.200 秒 |
| 3,000 | 0.355 秒 | 0.396 秒 |
| 5,000 | 0.596 秒 | 0.609 秒 |

优化前的同类 200 模型请求为 9.346 秒，缓存读取为 9.217 秒。优化后 200 模型结果的 SHA-256 与基线一致。全部模型数量完整，未通过截断目录提速。5,000 模型缓存读取的三轮范围为 0.598 至 1.108 秒。

8,775 条参考记录中的 8,365 个不同模型名称、别名及补充查询，与原扫描器逐一对照，差异为 0。官方协议的精确记录、规范名称、日期形式和首条优先规则也通过逐项对照。能力资料和协议查找均已移除批量加载中的逐模型全表扫描。

实际 VS Code 1.141.2 完成 200 个模型注册、两个模型的组内请求及 A、B、A 服务切换。6 次请求的模型和凭据正确，配置恢复及重启保留通过。两次目录读取为 327 ms 和 124 ms。上游为合成服务，不代替真实服务授权与完整对话续接验收。

实际编辑器首轮有 1 次调用遇到配置重载时模型提供方尚未注册。验收脚本已等待模型变更稳定，并在每次请求前重新读取模型对象；没有重试失败的模型请求。首次失败与最终成功记录分开保留。

机器数据见 [性能证据](evidence/model-catalog-index-20261027.json)。原始日志与隔离夹具保留在系统临时目录，未上传制品库。
