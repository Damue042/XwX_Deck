# Mac 更新验收准备

## 当前边界

本页是执行计划，不是通过报告。
Mac 前台可用，执行结果另行记录。
专用签名密钥已经批准并存入本机钥匙串。
共享来源、最终安装包和生产发布仍有阻塞。

更新助手已有签名验证和原子替换代码。
本轮修复后，换出的旧应用会保留。
系统接受启动请求仍不等于新版已正常运行。
启动健康握手和失败保留机制已写入本地候选。
隔离测试覆盖通信和目录交换。
真实签名验收构建已完成隔离下载、替换与重启。
正式发布包仍待最终来源审计与平台验收。
本轮范围见 [签名更新隔离验收](mac-signed-update-validation.md)。

## 隔离范围

在系统临时目录内创建独立验收根。
先解析真实路径，避免临时路径中的符号链接。
目录分为 `applications`、`data`、`downloads` 和 `evidence`。
只操作本次创建并登记的应用与进程。

基线与目标包均从同一冻结源码构建。
基线使用较低的测试版本号，不冒充历史发行包。
验收应用身份使用 `app.xwxdeck.validation`。
测试清单、版本和安装包哈希必须对应。

所有配置、Trace 和会话文件均使用合成内容。
测试前记录每个数据文件的 SHA-256。
测试后核对文件内容、目录选择和用户开关。
不复制正常安装的凭据、配置或会话正文。

## 启动健康握手

助手为每次更新创建私有 Unix socket。
目录权限为 `0700`，socket 权限为 `0600`。
每次生成新的随机挑战，不使用确认文件。
该挑战不是持久签名密钥。

连接身份由内核返回的用户和进程标识确认。
助手核对进程路径及目标可执行文件的 SHA-256。
客户端核对助手路径，并验证 Apple 签名身份。
消息必须匹配挑战、版本、进程和阶段。
旧文件、旧挑战或无关进程不能确认本次任务。

新版先在 `main` 入口申请访问许可。
获准前不打开配置、Trace 或凭据。
助手先记录已授权，再发送许可。
这样，许可发送时崩溃也不会误判数据未变。

后端快照加载成功且 React 界面提交后，发送健康确认。
初始加载有错误时不确认。
确认不依赖焦点或动画帧，支持后台启动。
助手返回接受消息后，客户端才结束握手。
该确认只证明启动阶段完成，不替代完整功能验收。

助手等待健康确认最多 60 秒。
消息大小和读取时间均有上限。
超时或失败时先关闭本次通道。
延迟启动的新版因此不能继续申请访问数据。

启动失败或健康确认超时，均不自动降级。
瞬时进程检查不能排除并发手动启动。
即使没有收到访问许可，新版也可能经其他启动路径打开数据。
因此，最终代码移除了有限自动恢复分支。
助手保留两份应用，并记录 `manualRecoveryRequired`。

不强制结束进程，也不跳过系统检查。
人工恢复前需核对运行进程、签名、版本和数据兼容性。
新版可能已更新数据格式，旧版不一定能够读取。
代码不会自动回滚配置、Trace 或会话文件。
人工恢复必须使用独立安装和数据副本。
验证结果见 [签名更新隔离验收](mac-signed-update-validation.md)。

恢复时先保留新版应用和原数据。
将数据副本放回本次测试的原路径。
这样可保留索引中的绝对路径引用。
核对旧应用的签名、版本和正文后，再检查界面。
关闭恢复副本的自动更新，防止再次安装同一候选。
该步骤不修改保留的原数据。

启动成功也不会自动删除备份。
清理需另行确认当前版本稳定、数据完整且备份未被占用。
当前没有自动清理入口。
替换前失败时，保留的暂存应用是待安装候选。
替换后失败时，暂存位置保留的是旧应用。
结果文件通过 `backupRole` 区分两者。

该通道用于拒绝过期或错误进程的确认。
它不能防御已完全控制同一用户会话的攻击者。
完整签名包的系统校验仍是独立前提。

## 执行矩阵

| 场景 | 应验证结果 |
| --- | --- |
| 正常更新 | 下载、验签、平台身份校验、替换和有效启动确认全部完成。 |
| 清单篡改或未知公钥 | 下载或安装停止，原应用和数据不变。 |
| 文件损坏、大小或哈希不符 | 不进入可安装状态。 |
| 错误架构、应用身份或未公证包 | 系统校验拒绝，原应用不变。 |
| 原应用未退出或文件被占用 | 不替换原应用，不强制结束用户进程。 |
| 下载后清单变化 | 要求重新检查，不安装旧选择。 |
| 替换前故障 | 原应用和数据保留，可正常重开。 |
| 系统拒绝启动 | 不报成功，保留两份应用和恢复依据。 |
| 启动后握手失败或超时 | 不报成功、不自动降级，保留两份应用。 |
| 过期、伪造或错误任务确认 | 拒绝确认，不删除恢复副本。 |
| 更新后重启 | 版本、语言、目录和开关符合预期，合成数据哈希一致。 |

## 执行前提

正式候选先完成共享来源审计，再冻结提交。
隔离诊断可先冻结本地源码，不能解除发布关口。
确认实际可用的 Apple 签名和公证身份。
若出现系统授权或安全提示，交由用户处理。
不绕过签名、公证、隔离属性或系统权限。

应用级签名清单验收还需明确的信任来源。
临时测试密钥只能用于独立测试构建或测试函数。
不能写入生产 `assets/update-trust.json`。
正式信任链的配置批准已取得，首次签名分发仍需实测。

清单生成和发布失败保护另有合成测试。
本页定义要求，不直接声明真实安装通过。
共享来源、正式分发和最终包验收仍是独立关口。

## 夜间触发

夜间安装需要当地时间在 2 点至 5 点之间。
2 点可安装，5 点停止触发。
连续闲置至少 15 分钟，且 Gateway 未运行。
用户关闭自动更新或拒绝当前版本时，不自动安装。
制品准备完成后，还需复查安装条件。

验收通过独立测试时钟驱动真实后台轮询。
不更改系统时间，也不伪造系统输入事件。
测试入口只编译到 `update-validation` 构建。
普通构建仍使用当地时间和系统闲置状态。
跨夜运行、系统睡眠和夏令时仍需独立验证。
