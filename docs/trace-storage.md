# Trace 正文存储

Trace 在会话内去重，并压缩正文。
每次请求仍保留独立记录。
仪表盘按需还原内容，查看方式保持一致。

## 文件与内容

每个会话最多使用两个文件。

| 文件 | 内容 |
| --- | --- |
| `<会话 ID>.jsonl` | 请求元数据、小正文和大正文引用 |
| `<会话 ID>.content.sqlite` | 去重后的 Zstd 压缩正文块 |

正文块包括较大的消息、工具定义和响应。
大字符串与大数组项分别成块。
小于 1 KiB 的内容留在 JSONL 中。
没有大正文的会话不创建正文库。

正文块按序列化内容的 SHA-256 值识别。
完全相同的内容共用一个块。
内容、顺序或工具标识变化时，保留实际差异。
不同会话使用各自的正文库。

JSONL 的 `_traceContent` 字段记录格式版本与引用。
引用使用 JSON Pointer，即 JSON 节点路径。
正文中的同名字段继续作为普通内容保存。
正文块不引用其他块，也不依赖前一条请求。

## 写入与读取

写入先提交正文库，再追加 JSONL 引用。
中断可能留下未引用的块。
这些块随会话一起清理。
写入不发布尚未提交的正文引用。

读取详情时，先解压正文块，再检查长度与哈希。
两侧请求、两侧响应及原始流分别还原。
请求次数、耗时、Token 与费用分别保留。
列表缓存只保留摘要。
分页预算按还原后的数据大小计算。

已有普通 JSONL 继续可读。
新格式只用于后续捕获，不自动改写历史。
备份或复制会话时，应同时保留两个文件。

## 清理与修复

容量统计包含记录文件和正文库的实际大小。
会话删除与自动清理同时移除两个文件。
正文共享范围止于会话，无需跨会话引用计数。
0 GB 清理正文，继续独立保留用量统计。
已有容量与自动清理选择保持有效。

索引修复只在用户发起后执行。
修复先备份索引，不改写 JSONL 或正文库。
正文库缺失、版本无效或校验失败时，明确报错。
修复不会跳过损坏正文后覆盖索引。

验收场景见 [Trace 状态矩阵](maintenance/trace-state-acceptance.md)。
