# Provider 路由维护规则

本文约束协议、切换、续接和客户端适配。
产品范围以 [产品定义](product.md) 为准。
执行方式见 [开发与测试流程](development-testing-workflow.md)。
当前验收结果仍见 [整合验收](maintenance/integration-acceptance.md)。
本文不把维护目标视为已通过验收。

## 维护方式

沿用现有 Rust Gateway 和配置账本。
每次修复只调整对应规则与消费链路。
修复前先增加能够复现问题的断言。
不另建 Provider 注册表或第二套后端。

每条兼容规则应说明以下内容。

- 适用的服务、端点、模型和客户端版本。
- 官方说明或可重复的请求证据。
- 规则与服务明确声明的优先关系。
- 原请求与实际上游请求的区别。
- 对应的正常、失败和恢复回归。

规则属于兼容策略。
规则命中不等于目标服务已经验收。

## 成熟实现复用

修改前先对照参考实现及 Deck 现有逻辑。
已有逻辑能满足目标时，保留实现并补足回归。
存在明确缺口时，优先复用成熟代码或移植其逻辑。

| 情况 | 处理方式 |
| --- | --- |
| 语言兼容、依赖独立 | 直接复用，接入现有模块接口 |
| 后端算法成熟，语言不同 | 移植为 Rust，保留语义和边界案例 |
| Deck 已有对应机制 | 核对差异，避免增加重复模块 |
| 依赖上游数据库或运行框架 | 只适配必要逻辑，沿用现有状态所有权 |

复用时记录仓库、提交、文件及适用范围。
核对具体代码和依赖的许可证。
复制代码时保留要求的版权及许可声明。
移植时同时保留相关回归案例。
删除与 Deck 无关的接入分支，保留必要异常处理。
不能为缩短代码而省略身份、取消或恢复检查。

复用验收检查可观察行为。
代码结构可以不同，状态边界应保持准确。
只有请求成功不够，还需核对失败、续接和恢复。
移植后仍只保留一套能力判定和状态来源。

### 当前核对结论

下表记录源码比较结果，不替代实际验收。

| 机制 | Deck 当前实现 | 维护决定 |
| --- | --- | --- |
| 原生协议优先 | API 与订阅共用 `catalog::preferred_wire` | 沿用共同逻辑和跨语言案例 |
| 认证续期去重 | API 授权与 Copilot 串行续期并原子保存；Grok 使用续期锁 | 保留已有机制，按身份与失败场景补查，暂不增加另一套缓存 |
| 会话账号绑定 | 可用候选排序优先保留当前会话绑定 | 保留既有选择器，核对失效及手动选择边界 |
| 错误分类 | 账号池与服务切换共用 `routing_errors::quota_error` | 仅依据错误字段确认额度耗尽，忽略无关 quota 字段 |

源码比较只证明机制存在。
锁的范围、失败时并发行为和跨进程续期需分别验证。
已有回归结果按候选和测试环境引用。

## 协议与能力

服务有效声明优先于厂商及型号规则。
厂商规则不能证明聚合站提供相同端点。
未知能力保留未知状态。

客户端优先使用自身的原生协议。
Codex 优先 Responses，Claude 优先 Messages。
缺少原生入口时，再选择可用的转换。
其他条件相同时，Responses 优先于 Chat。
目录返回的端点顺序不影响选择。

普通 API 与订阅共用协议优先级函数。
前端与 Rust 使用同一组协议组合案例。
案例位于 `src/shared/protocol-routing-cases.json`。
回归入口为 `tools/native/model-protocols-test.mjs`。
Rust 合同检查与实际订阅请求分别验证。

参数支持与协议支持分别判断。
单个参数失败不能触发账号轮换。
不能静默删除工具、图片或必要上下文。
推荐上下文、最大容量和用户选择分别保存。
资料更新不能覆盖用户的明确选择。

## 额度错误分类

账号池和服务切换使用同一额度判定。
HTTP 拒绝和流内错误使用同一组错误证据。
判定只读取结构化错误的代码、类型和消息。
响应其他位置出现 quota 不表示额度耗尽。
临时限流不能触发跨服务切换。

分类函数位于 `src-native/src/routing_errors.rs`。
跨服务回归为 `tools/native/service-switching-pool-test.mjs`。
该回归覆盖临时限流和确定额度耗尽。
原生单测同时覆盖流内错误及无关正文。

## 切换与认证

使用稳定 ID 绑定连接及账号身份。
名称相同不表示连接相同。
访问令牌续期不表示用户切换账号。
Key、请求头和地址不能跨连接混用。

一次请求使用完整的路由快照。
回答中切换服务不改变已经开始的请求。
后续请求采用最新的有效选择。
客户端保留旧绑定时，说明实际生效边界。

本地保存不依赖远端目录健康。
迟到结果不能撤销新选择。
保存、配置写入、运行时采用和生成分别确认。

认证续期与 Trace 开关分别管理。
并发请求对同一身份合并续期操作。
续期结果只更新原来绑定的身份。
客户端原生认证能力需单独验收。

## 对话续接

健康会话优先保留已有账号绑定。
手动切换与自动故障切换分别处理。
已有绑定不能覆盖用户新的明确选择。

原生响应标识受来源服务和账号约束。
跨服务不能直接复用原生响应标识。
迁移使用来源明确的历史或检查点。
加密状态不能冒充可移植历史。
缺少必要上下文时，返回明确的恢复提示。

工具调用和结果保持 ID、顺序与完成状态。
已执行工具不能因切换而重复执行。
已有输出或执行结果不确定时，不整轮重放。
取消后关闭对应上游连接。

## 客户端适配

沿用共享客户端目录及已保存的管理列表。
安装检测不自动授予模型管理能力。
Desktop、CLI 和插件分别验收。
检测需核对实际安装、配置覆盖和版本能力。

配置写入只修改受管字段。
恢复需核对当前字段及所有权证据。
外部修改不能被旧备份覆盖。
无法管理模型的条目只保留下载入口。

参考 [客户端管理范围](maintenance/client-management-scope.md)。

## 必须保留的验收场景

| 场景 | 核心断言 |
| --- | --- |
| A→B→A，旧目录迟到 | 最后选择、账号和模型不回退 |
| 回答中切换 | 原回答完成，下一轮采用新绑定 |
| 同线程跨服务续接 | 正文、检查点和工具结果保持关联 |
| 重启后恢复原线程 | 持久状态与实际路由一致 |
| 并发会话及账号 | 上下文、凭据和冷却状态不串用 |
| 参数错误、限流、额度耗尽 | 按原因处理，不扩大故障范围 |
| 输出后断流或取消 | 不重复生成，不重复执行工具 |
| 外部修改后恢复配置 | 保留外部字段，冲突可继续处理 |
| Windows 与 macOS | 分平台验证实际客户端读取 |

实际请求检查目录、端点、认证和响应。
新建成功对话不能代替原线程续接。
合成服务、正式上游和界面检查分别记录。
