# 模型与客户端

为每个客户端选择服务，确认模型实际使用的请求路径。

## 选择服务和模型

1. 打开模型页，选择需要配置的客户端。
2. 选择已保存的服务。
3. 从模型列表中选择型号。
4. 在客户端发起一段测试对话。

每个连接分别保存客户端的模型设置。
不同客户端可以选择不同连接。
添加配置、导入账号或刷新目录都不会自动切换选择。

## 模型目录

列表先显示同一连接的成功缓存，再后台刷新。
目录离线时，保留已有模型与最后选择。
模型菜单只列实际目录，不提供手动输入型号的入口。

已有的自定义型号或下线型号仍会保留，并标明状态。
XwX Deck 不会自动换成其他型号。
如果列表为空，请核对地址、密钥和模型目录权限。

服务声明的协议与能力优先采用。
缺少证据时，不凭品牌或型号名称猜测。
接口差异见 [接口与兼容边界](provider-compatibility.md)。

## 理解“需 Trace”

Trace 开启后，本机 Gateway 接收已接入客户端的请求。
需要协议转换或 Desktop 别名转发的模型会标记“需 Trace”。
关闭 Trace 后，这些模型需要重新开启网关才能使用。

| 接口 | 请求处理 |
| --- | --- |
| OpenAI Responses | 沿用 Responses 协议转发。 |
| OpenAI Chat Completions | 在本机转换兼容请求。 |
| Anthropic Messages | 原生使用或按客户端要求转换。 |

图片输入、图片生成和工具调用是不同能力。
能否使用取决于模型、服务商与客户端的共同支持。
转换无法保留必要语义时，会返回错误。

## 管理客户端

模型页的“客户端管理”打开统一管理窗口。
可以添加、隐藏客户端入口，或重新检测安装状态。
未安装时，可通过官方下载入口获取客户端。

移除入口只隐藏标签，不卸载客户端。
已有模型配置继续保留。
下载入口也不代表该客户端已经完成接入。

Codex、Claude、OpenCode、Gemini CLI、Qwen Code 等提供受管配置。
其他客户端按界面提示手动接入。
安装检测、配置写入和实际请求验证分别进行。
快速开始以 Codex 为例；具体兼容性以对应客户端的验证结果为准。

Qoder 等需手动配置的客户端，应使用其官方向导。
仅在向导允许时填写界面提供的 Gateway 信息。

## 切换后继续对话

切换服务后，在同一段测试对话中继续提问。
核对上下文、实际路由和会话归属。
另开对话成功不能证明原会话可以续接。

部分客户端会缓存配置。
如果新请求仍使用旧连接，请重新打开客户端后再试。
XwX Deck 不会为切换服务自动重启客户端。

第三方模型配置用于已接入客户端的模型请求。
ChatGPT 网页普通聊天仍按网页自身的规则运行。
