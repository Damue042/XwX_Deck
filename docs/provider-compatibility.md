# 接口与兼容边界

先确认连接的实际接口，再判断客户端与模型是否可用。

## 连接信息

每个连接独立保存名称、地址、密钥和客户端偏好。
普通配置表单只展示必要字段。
已有的明确协议设置会保留。
Claude 与 Codex 可以使用不同连接。

API 按量服务与 Coding Plan 套餐可能使用专属地址。
地址、权限和模型可用性以服务商资料为准。
不能只凭品牌或模型名推断协议。

## 请求协议

| 协议 | 当前处理方式 |
| --- | --- |
| OpenAI Responses | 按 Responses 转发。 |
| OpenAI Chat Completions | 在本机适配兼容的请求与响应。 |
| Anthropic Messages | 原生使用，或在本机进行协议适配。 |
| Gemini 原生接口 | 可以识别相关目录；不据此声明支持原生请求转换。 |

服务商有效声明的协议逐字段优先采用。
普通能力缺项由外部模型资料补充，并保留来源。
证据不足时，沿用连接的实际协议。
需要协议转换的请求依赖本机 Gateway。

## 地址与目录

接口地址需要保留服务商要求的路径前缀。
例如 `/v1` 与 `/api/v3` 是不同的版本路径。
不要在已有前缀后重复添加 `/v1`。

模型列表来自当前连接的实际目录。
目录失败时，保留同一连接的成功缓存与已有选择。
保存配置不依赖目录健康。

模型菜单不提供手动输入型号的入口。
已有的自定义或下线型号会保留，并标明状态。
目录可见不等于当前账号有调用权限。

## 认证与身份

普通 API 使用连接保存的密钥。
Bearer Token 与 Anthropic `x-api-key` 按实际接口处理。
官方授权账号使用对应的授权链路。

任意自定义请求头、Azure 专用路径或 AWS 签名等形式，
需要单独支持，不能按普通兼容接口推定可用。
使用前请核对当前版本的实际能力。

账号、密钥和模型目录属于同一连接。
切换连接不会把上一服务的凭据发送至新服务。

## 工具、图片与流式响应

图片输入、图片生成与工具调用需要分别确认。
支持其中一种能力，不代表其余能力也可用。

用户开关继续有效。
XwX Deck 不按服务品牌统一禁用生图工具。
上游服务返回实际能力和错误。
协议转换无法保留必要语义时，会明确报错。

流式响应、工具结果与可携带历史按真实记录保留。
不完整响应不会被补成完成状态。
缺失用量也不会被推算成可靠数值。

## 验证兼容性

1. 保存连接，选择实际目录中的模型。
2. 按提示开启 Trace。
3. 在客户端发送一段测试对话。
4. 核对实际上游、输出与用量。
5. 如需切换服务，在同一段对话中验证续接。

不同服务和套餐的支持范围可能不同。
遇到授权、额度或计费问题时，同时核对服务商后台。
