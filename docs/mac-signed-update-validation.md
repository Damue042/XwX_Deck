# Mac 签名更新隔离验收

本流程只生成独立验收应用。
生产更新开关、稳定清单和正常安装保持不变。
程序必须使用 `app.xwxdeck.validation` 身份。
数据和应用目录必须属于同一个测试任务。

## 安全范围

测试服务仅监听本机回环地址，使用 HTTPS。
临时证书只供验收构建信任，不加入系统钥匙串。
证书链、主机名和签名检查保持开启。
测试清单使用独立公钥和 `mac-validation` 频道。
生产客户端不接受该频道，也不信任测试公钥。
临时私钥不进入源码或正式信任文件。

应用和 DMG 使用现有 Developer ID 签名。
公证、票据装订和系统检查按正常流程执行。
不会移除隔离属性或关闭 Gatekeeper。
测试制品不得上传到正式下载路径。

## 执行方法

先在独立终端运行本机测试服务。
目录必须是新的专用测试目录。

```sh
node tools/native/macos-update-validation-server.mjs /private/tmp/xwx-signed-update-acceptance-1
```

另一个终端运行验收。
测试使用两个独立的应用版本标签。
两者均来自本轮冻结源码，不冒充历史客户端。

```sh
node tools/native/macos-update-validation-test.mjs /private/tmp/xwx-signed-update-acceptance-1
```

测试包含错误清单签名、网络失败、坏哈希和平台签名拒绝。
随后执行实际下载、替换和启动健康确认。
另一个场景暂不发送健康确认，检查超时和备份保留。
该故障注入只存在于 `update-validation` 构建。

验收通过后保留应用、备份、哈希和报告。
结束测试服务时，删除本次临时 TLS 私钥。
正式签名私钥不会被此流程读取或改动。
通过只证明报告列明的本机架构和合成数据场景。
Windows、其他架构及最终生产包仍需分别验收。
