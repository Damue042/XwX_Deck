# Trace 与用量

在本机查看请求过程，理解 Token、参考费用与数据保留规则。

## 开始追踪

1. 在 Trace 页开启追踪。
2. 按提示完成客户端接入。
3. 在客户端新建一段测试对话。
4. 打开仪表盘，检查会话与实际请求。

只有经过本机 Gateway 的请求才会进入本次追踪。
开启前的历史对话不会凭空补齐。
客户端的标题生成、预热等辅助请求也可能产生记录。

## 阅读请求详情

在仪表盘选择会话，再打开需要查看的请求。
详情分别保留客户端原请求、转换后的上游请求和响应。
排查问题时，应核对实际服务、模型和错误信息。

首次进入会话会打开最新请求。
阅读时收到新请求，不会跳走当前阅读位置。
返回和刷新保留选中请求与滚动位置。
关闭仪表盘窗口后，本次阅读位置会清除。

## 理解用量和费用

| 显示 | 含义 |
| --- | --- |
| Token | 服务返回的输入、输出及缓存等用量。 |
| 已知金额 | 按捕获时保存的价格与用量计算。 |
| `0` | 已知值为零。 |
| `—` | 缺少可靠数据，当前值未知。 |
| 耗时 | 记录的请求处理时间。 |

缓存和推理用量按对应计费语义处理，避免重复计算。
价格与汇率随请求保存，不随目录更新而改写历史。
失败且没有计费用量的请求不会生成已知费用。

参考费用不等同于服务商账单。
订阅的参考费用也不代表账号实际扣款。
需要对账时，请同时核对服务商后台。

## 容量与自动清理

新配置默认上限为 1 GB，并开启“超出上限自动清理”。
已有明确的容量和自动清理选择会保留。
可在设置的 Trace 分组中调整。

自动清理从较旧的完整对话开始，保留正在记录的对话。
自动清理只删除详细记录，Token 和费用统计继续保留。
关闭自动清理后，容量上限仅用于提醒。

开启“仅记录用量”，只统计 Token 和费用，不保存请求与响应正文。
确认后清理详细 Trace，后续请求继续累计统计。
容量和自动清理设置保留显示并停用。关闭后恢复原选择，仅保存后续请求的详情。
已有统计仅在额外勾选清空时删除。

## 手动删除和修复

仪表盘手动删除默认保留用量统计。
只有额外勾选删除对应统计时，才会一并删除。

索引缺失或损坏时，在“诊断与修复”中检查 Trace 记录。
先停止 Gateway，再手动发起修复。
修复会备份原索引，不修改原始 JSONL 记录。
索引修复用于 Deck 记录，不修复客户端会话历史。

## 停止和退出

停止 Trace 会恢复受管连接并关闭 Gateway。
最后选择的服务和模型继续保存。
需要协议转换的模型，下次使用时须重新开启 Trace。

关闭主窗口可能只会隐藏应用，Gateway 继续运行。
使用托盘、菜单栏或退出命令，才会进入安全退出流程。
活动请求、工具等待和外部配置冲突会分别提示处理。

## 分享前检查

Trace 保存在本机数据目录。
记录可能包含提示词、上下文、工具参数和模型响应。
认证请求头会脱敏，业务正文仍需人工检查。
分享日志或截图前，请移除密钥、身份与业务敏感信息。
