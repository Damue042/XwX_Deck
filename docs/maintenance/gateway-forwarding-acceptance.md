# Gateway 普通接口转发

后续真实生图及签名包结果见 [生图修复验收](gateway-image-repair-acceptance.md)。

## 行为要求

Gateway 在入口区分模型协议和普通接口。
已识别的模型协议沿用转换、续接和 Trace。
其他接口按客户端原始来源转发。
解析能力不决定接口能否转发。

开启 Trace 前保存来源快照。
Codex 和 Claude 使用独立来源。
官方账号接口保留独立地址。
普通接口不跟随模型服务切换。
重启时从已有字段恢复账本读取来源。
其他客户端的手动入口绑定已选择的 API 服务。
新增客户端可以补充绑定，已有绑定保持稳定。

普通接口保留方法、路径、查询、正文和响应状态。
上传与下载均按数据流传输。
不应用 Trace 的正文大小限制或对话读取超时。
不解压正文，不跟随重定向，不自动重试。
WebSocket 保留文本、二进制、子协议和关闭状态。
HTTP 和 WebSocket 均沿用系统代理与 TLS。
连接专用请求头由传输层清理。

普通接口不生成对话 Trace，也不记录正文。
模型服务的 Key、Cookie 和账号字段不得跨来源发送。
无法取得原始地址或凭据时，返回可操作错误。
不得借用其他订阅账号。
取消与强制停止会关闭对应上游传输。
普通停止继续检查在途请求。

## 实现位置

- `src-native/src/gateway_forwarding.rs`：来源快照、协议识别和凭据边界。
- `src-native/src/gateway_transport.rs`：HTTP 和 WebSocket 字节传输。
- `src-native/src/ingress.rs`：在解压、解析和服务切换前分流。
- `src-native/src/clients.rs`：Claude 使用 `/_xwx/claude` 独立入口。

原有无前缀模型入口继续兼容。
旧客户端应重新读取配置，才能使用独立普通接口入口。
来源快照复用现有恢复账本。
本次不新增客户端配置导入或订阅登录流程。
