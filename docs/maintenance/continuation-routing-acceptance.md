# 旧会话连接与续接验收

验收日期：2026-10-17。
本轮修改源码、测试和文档。
正常安装、官方登录文件和原会话保持原样。

## 原因

独立应用分别使用自己的 Gateway 端口，避免同时运行时争用监听。
Codex 旧会话会保留 `xwx_deck` 服务绑定。
切换管理应用后，默认服务可以已更新，但旧绑定仍指向停止的本地端口。
正在运行的 Codex 进程也可能保留已加载的地址。
这类本地连接失败不能直接归为上下文丢失或订阅失效。

## 修复规则

1. 检查未激活的旧会话绑定。发现其他本地代理的配置时，显示外部配置状态。
2. 用户可选择目标服务，也可点击“接管当前服务”。两条入口均先确认备份。
3. 接管后将旧会话绑定写为当前目标，同时保留默认服务选择与无关字段。
4. 官方直连绑定移除旧 Bearer 和环境变量凭据选择器，保留官方登录文件。
5. 仅清理与旧绑定指向同一地址来源、且符合标准 Gateway 路径的全局代理覆盖。其他自定义模型和账号地址保留。
6. 开启 Trace 后将受管绑定更新为当前端口，安全停止后恢复可用直连。
7. 已添加的订阅服务接管旧本地代理时，先建立可恢复的直连基线，再进入订阅 Gateway。
8. 地址变化后提示等待当前回答结束，重启 Codex，再打开原会话继续。
9. 修复活动配置时一并修复本 Gateway 改过的旧绑定字段，保留无关外部变化及原文件备份。

配置所有权同时核对账本与当前实际字段。
旧账本不能掩盖其他应用后来写入的地址。

不修改原会话的服务字段或历史正文。
`xwx_deck` 是共享绑定名称，不能单凭它认定加密上下文来自其他上游。
已知来源冲突仍按既有转换规则处理，未知原生状态交由目标服务验证。
失败后不自动换服务或重放请求。

## 大历史处理

同服务、账号和模型的原生续接保留 `previous_response_id` 与本次增量。
跨服务时才恢复对应明文检查点及后续记录。
来源判断只读 SQLite 元数据和首条 `session_meta`。
历史总大小超过 64 MiB 不再触发误拦截。
正文恢复按精确窗口读取，保留已有上下文与单记录边界。
读取通过阻塞任务执行，不占用续接缓存锁。
当前检查点、压缩来源和归属记录不会作为旧缓存清理。
工具结果按原生响应关联，不重复注入或执行已完成的工具。
