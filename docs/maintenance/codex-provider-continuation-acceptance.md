# Codex 目录与跨服务续接验收

本轮针对用户报告的启动失败和续接问题。
用户从官方订阅切到 用户配置的中转服务。
切换前后均使用 `gpt-6.1-sol`。
当时 Trace 已开启。
加密错误的完整原文已不可取得。

## 原因与修复

### 模型目录

生成器复制客户端的精确型号记录。
旧代码随后删除了 `model_messages`。
当前客户端把指令放在该字段的模板中。
部分型号因此失去有效指令。
`codex-auto-review` 是其中一个型号。
通用中转服务也使用这个生成器。

修复保留完整的原生指令模板。
已有 `base_instructions` 继续保留。
两种指令均缺失时才补充基础指令。
不把带占位符的模板展平成普通文字。

目录修复已写入当前生成器。
新生成目录使用有效指令模板。
实际客户端加载仍需单独验证。

### 上下文默认值

模型容量与客户端默认窗口分别维护。
服务的有效声明仍然优先。
缺少声明时，普通能力继续读取 models.dev。
精确型号的客户端缓存提供运行默认值。
默认值不会超过已核验的服务容量。

本机当前资料分别为：

| 项目 | 数值 | 来源 |
| --- | --- | --- |
| 型号容量 | 1,050,000 Token | 已保存的 models.dev 资料 |
| 客户端默认窗口 | 500,000 Token | 当前原生型号缓存 |
| 连接中的旧窗口选择 | 262,144 Token | 已保存的明确配置 |

旧选择器把默认项固定为 256K。
修复后，默认项随当前客户端资料更新。
选择默认项会移除固定窗口覆盖。
可选的 1M 窗口继续作为明确选择。
已保存的窗口选择保留，不静默改写。
需要使用新默认值时，重新选择默认窗口。

这些数值是本机资料核对结果。
它们不证明服务实际支持相应输入长度。
长上下文生成仍须独立实测。

### 加密压缩上下文

网关此前只能恢复自己观察到的压缩来源。
客户端已有的压缩项可能早于网关记录。
这种来源的缓存可能标为不完整。
仅清除加密项会丢失压缩前的内容。

修复补充当前客户端的精确线程恢复。
它通过只读 SQLite 索引定位原生历史。
路径必须位于客户端的受管历史目录。
会话 ID 和加密压缩项必须完全匹配。
恢复只修改待转发的请求副本。
原始历史、授权和客户端请求保持不变。

恢复保留可见消息和已完成的工具结果。
它不再次执行历史工具。
多个压缩点保留已确认的完整前缀。
缺少前缀、路径冲突和不完整文件明确失败。
读取上限为 64 MB，携带上下文上限为 8 MB。
原文件正在变化时，用户可以重试续接。

恢复仅针对当前客户端的续接请求。
它通过精确线程索引定位对应历史。
XwX Deck 没有旧发行版本迁移需求。
本轮不添加其他产品的数据兼容。
不提供对话诊断页面或后台正文扫描。

## 程序化覆盖

新增脚本为 `tools/native/codex-client-compatibility-test.mjs`。
它使用实际 Rust 网关和合成的本地上游。
共享选择器断言位于 `tools/shared-core/codex-client-contract-test.mjs`。
两者均已纳入默认原生回归。
功能编号为 MO01、CL01、CL02 和 TR05。

| 场景 | 核心断言 | 层级 |
| --- | --- | --- |
| 当前模板与旧指令格式 | 每条发布记录至少保留一种有效指令 | P |
| 客户端资料刷新 | 500K 更新为 600K，不冻结 TOML 覆盖 | P |
| 服务明确限制 | 服务的 128K 声明优先 | P |
| Trace 开启后切换 | 同一监听器、同一线程、同一 GPT 型号 | P |
| 已有原生压缩项 | 精确历史恢复，工具调用与结果配对 | P |
| 网关已有压缩来源 | 最新指令保留，历史前缀只出现一次 | P |
| WebSocket 续接 | 同一压缩点恢复，原历史字节不变 | P |
| 未匹配压缩项 | 转发前失败，上游请求数量不增加 | P |
| Trace 原文与实际上游 | 原请求保留加密项，上游记录显示恢复内容 | P |
| 多个压缩点与缺失前缀 | 完整前缀保留，不把后缀冒充完整历史 | P |

实际 Codex CLI 的目录消费另行验证。
本机版本为 `0.162.1`。
隔离配置使用合成授权，并阻断外网访问。
只执行初始化和模型列表读取。
修复前复现用户的目录解析错误。
修复后读取当前生成器产出的完整目录。
没有发送生成请求。
这是实际客户端解析证据，不是上游续接验收。

完整回归的结果与制品见 [交付记录](codex-provider-repair-delivery.md)。

## 真实环境待验

实际客户端须验证官方订阅到用户中转服务。
全过程保持 Trace 开启。
先新建测试会话，再实际触发压缩。
切换后续接同一原生线程。
核对前文标记、实际上游和 Trace 归属。
重开客户端后再恢复同一线程。
不能用另开新会话代替续接验证。

HTTP 和 WebSocket 分开登记。
实际 Desktop 的加载和操作分别登记。
当前程序化结果不替代这些真实环境项目。
