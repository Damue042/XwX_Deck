# VS Code Copilot 模型接入

模型页和 Trace 页的“VS Code Copilot”接入 VS Code 的 Copilot Chat。它通过自定义模型组发送聊天模型请求，代码补全不在接管范围内。GitHub Copilot CLI 是独立入口。

## 使用

1. 在模型页选择“VS Code Copilot”，设置模型服务和默认模型。
2. 开启 Trace，将该服务目录中可用的对话模型写入 Copilot 的 `XwX Deck` 模型组。
3. 在 Copilot 聊天框的模型选择器中切换模型。切换模型不需要回到 Deck 修改默认值。

手动填写且不在目录中的默认模型会保留。重复、无效、已下线和非对话模型不会批量写入。每个模型分别配置协议和已知能力，个人模型组保持原样；关闭 Trace 后按恢复记录还原。

说明放在“模型服务”的悬停提示中，不增加常驻说明区。VS Code 的配置格式与功能范围见 [官方文档](https://code.visualstudio.com/docs/agent-customization/language-models#_add-a-custom-endpoint-model)。

## 2026-10-27 验证

- 3,000 个目录模型加 1 个手动模型完整生成，无截断；协议、能力、去重及过滤检查通过。
- 实际 React 控件的 15 组回归通过，包括入口名称、悬停说明和保存后的 Copilot 选模提示。
- 隔离配置回归通过，覆盖组内另一个模型的真实回环请求、默认模型保留、外部修改保护及原配置恢复。
- 本机实际 VS Code 1.141.2 注册 200 个模型，按 A、B、A 切换服务，每个阶段分别请求两个模型。6 次请求的模型、服务和凭据均正确；恢复和重启保留检查通过。上游为本地合成服务，不代表真实服务授权通过。

首轮 200 个模型的目录读取超过测试默认的 15 秒期限。调试程序将测试等待调整为 60 秒后，两次读取分别为 49,801 ms 和 53,093 ms，随后编辑器检查通过。这是目录能力匹配阶段的实测耗时，尚未优化，也不作为发布版性能结论。首轮失败和最终结果分别保留。

本轮未替换已交付的 Windows 包。真实服务授权和完整对话续接仍按真实环境流程单独验收。
