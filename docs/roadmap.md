# Roadmap

> 本文保留早期设计与实现记录。
> 当前架构见 [运行架构](architecture.md)，验证状态见 [整合验收](maintenance/integration-acceptance.md)。

## 0.1.x

- 稳定独立 appId、数据目录、端口和构建流程；
- 验证 Claude / ChatGPT 官方与兼容服务的 Trace、模型切换和恢复；
- 验证分档/峰谷计费、实际服务模型名和缓存 TTL 用量读数；
- 持续复核当前 Gateway 实测能力，避免给模型展示无法兑现的推理档位；
- 验证快速修复、应用重置与强制退出恢复的跨平台安全边界；
- 验证 Rust 原生宿主、模型路由、Trace 记录与退出恢复的行为一致性；
- 完成公开许可证、隐私说明和安全报告渠道决策；
- 建立签名、公证和公共 HTTPS 更新服务后，再启用自动更新。

## 不在当前范围

- 客户端配置同步；
- Excel / CSV 转 Markdown；
- 局域网发布与管理工具。

## 订阅与客户端管理

已完成客户端标签和末尾「…」添加客户端入口、设置页模型配置同一行添加入口、单窗口三类别配置。添加客户端详情中可保存模型页标签，安装本身不会自动添加；Codex CLI 和 Claude Code 打开已有 ChatGPT 和 Claude 配置，不重复创建标签。当前订阅适配为 ChatGPT、Grok、GitHub Copilot、Claude 和 Cursor；官网用量跳转不等于已读取账号额度。

待实现：

- Copilot、Claude 和 Cursor 已通过隔离本地授权、实际请求与工具调用回归。2026-10-09 的用户授权验收读取 Copilot 10 个模型，GPT-4.1 经本地 Responses 转换到 Copilot Chat Completions 返回 HTTP 200；Cursor 读取 44 个模型，Auto 经原生 Connect 协议返回 HTTP 200。该 Cursor 免费账号使用指定模型的拒绝原因和 HTTP 429 也正确传回客户端。测试后恢复直连并清除临时凭证副本，未改动用户当前客户端和模型选择。Claude 的真实套餐兼容性仍需用户登录后验收；Cursor 付费模型及两种服务的真实工具执行尚待验收。继续补官方额度读取、Claude CLI 请求桥接、Gemini / Antigravity 等账号适配。每种接入验证登录、刷新、工具调用、取消和跨客户端实际请求，不用 API Key 表单替代订阅登录。
- 每个订阅类别提供一个可选择的账号组，组内管理多个账号。保留已有逐账号连接与明确模型选择，用户主动选择账号组后才启用组内策略。策略为手动指定、剩余额度最多优先、最少优先和均衡使用。比较官方有效窗口的剩余比例与重置时间，未知额度不伪装成 0 或 100%。本地请求统计与套餐额度分开。
- 同一会话固定账号；续接依赖原账号的会话不跨账号转发。额度耗尽或限流的切换必须在未输出响应前进行；不重放已输出的回复或工具执行。
- 客户端检测以安装路径、CLI 和配置痕迹为依据，默认显示已安装、已配置和用户保留的客户端；检测失败保留上次选择。安装与模型路由是两种独立能力，仅有下载入口不能宣称支持接管。常用客户端保留标签，更多客户端通过末尾「…」选择；完整下载目录从「添加客户端」进入。已添加但尚未实现接管的客户端显示独立的手动配置页面，不显示其他客户端的模型控件。

参考 [Magpie 的订阅与路由](https://github.com/yetone/magpie#sign-in-once-use-it-everywhere)。这些待实现项尚无可用策略开关，不影响现有账号路由。
